# FORMAI · VR / AR-студия

Виртуальная галерея для просмотра 3D-моделей в браузере и Meta Quest 3. React, Three.js, WebXR; статическое приложение для GitHub Pages.

## Возможности

- Каталог в браузере и VR: **Art** → 43 позы в пяти папках с исходными названиями; **Arch** → робот, архитектура, узел. Путь и кнопка возврата позволяют переходить между уровнями. Импортированные файлы доступны через «Свои модели».

- Все 43 референса доступны в веб-каталоге и VR без импорта файлов. Исходные LOD0 и разрешение 4K/8K сохранены. Готовые GLB со всеми дополнительными картами используют KTX2 UASTC уровня 4 + Zstd 18, без RDO. Пока конвертация конкретной позы не завершена, доступна её исходная PNG-версия или уже готовая версия с KTX2-картой цвета.
- Комната с PBR-освещением, PMREM окружением, ACES tone mapping, тенями и регулировкой экспозиции.
- Импорт GLB/glTF, FBX, OBJ + MTL, STL, PLY, DAE. Загрузка нескольких файлов, папки, drag-and-drop или прямой HTTPS-ссылки.
- PBR metal/rough материалы glTF: base color, normal, roughness, metallic, AO, emissive; стандартные расширения физических материалов Three.js. Draco, Meshopt и KTX2 декодируются локальными библиотеками из сборки.
- Скелетная и объектная анимация: список встроенных клипов, плавное переключение, пауза, скорость 0.25–2×.
- До 12 моделей в одной комнате; положение, вращение, масштаб, фокусировка камеры.
- Локальная коллекция файлов в IndexedDB. Перезагрузка восстанавливает файлы; трансформации и выбор клипа пока не сохраняются.
- Собственный демонстрационный робот с настоящим SkinnedMesh, 11 костями и 3 клипами. На этапе сборки экспортируется в GLB и в приложении проходит обычный GLTFLoader.
- Пространственное меню Quest 3: коллекция, трансформации, клипы и перемотка, свет и сцена. Импорт файлов доступен в веб-версии до входа в VR.
- Официальные модели Touch Plus с анимацией кнопок и стиков, два луча с курсорами, подсветка выбранной модели, тактильный отклик при поддержке браузером.

## Quest 3

1. Откройте опубликованный HTTPS-адрес в **Meta Quest Browser**.
2. Выберите любую позу. Можно сразу войти в VR и выбрать позу в пространственном меню → Коллекция → Art → исходная папка. Файлы на шлем переносить не нужно.
3. Нажмите **Войти в VR** и разрешите immersive-сеанс.

| Управление | Действие |
| --- | --- |
| Луч + курок | Выбрать объект или нажать кнопку панели |
| Левый стик вперёд + луч на пол, затем отпустить стик | Телепортация в допустимую точку |
| Боковая кнопка контроллера | Захват и перемещение/вращение модели |
| Два захвата, руки вместе/врозь | Масштаб и вращение модели |
| Правый стик влево/вправо | Плавный поворот вокруг головы, до 90°/с; сильнее отклонение — быстрее |
| Правый стик вперёд/назад | Плавное движение по горизонтальному направлению взгляда, до 1,2 м/с; отпустить — остановиться |
| Правый захват + правый стик вперёд/назад | Увеличить/уменьшить выбранную модель; сильнее отклонение — быстрее. Ходьба и поворот отключаются до отпускания захвата |
| X на левом / A на правом | Открыть или закрыть основное меню |
| B на правом | Открыть или закрыть меню материалов выбранной модели |
| B → Выгрузить из комнаты | Убрать выбранную модель и освободить её ресурсы, сохранив файл в локальном хранилище и позу в каталоге |
| Y на левом | Вернуть активное меню перед собой |
| Меню → Объект | Масштаб, вращение, XYZ с шагом 10 см, сброс, подойти, удаление |
| Меню → Анимация | Все встроенные клипы, пауза, перемотка, скорость |
| Меню → Сцена | PBR-освещение, экспозиция, сетка, автовращение, вход в галерею |

Меню материалов показывает карты, доступные у выбранной модели: все материалы вместе или отдельный материал, по четыре ползунка на страницу. Диапазон 0–10: 0 отключает вклад карты, 1 сохраняет исходный вид, значения выше 1 усиливают влияние. Для основной карты цвета 0 показывает цвет материала с сохранением прозрачности ресниц и глаз. «Сбросить» возвращает выбранные материалы к 1. Настройки действуют, пока модель загружена; после повторной загрузки используется исходный вид. Ползунки не требуют повторной компиляции шейдера.

Основное меню закрепляется в пространстве на расстоянии 1,35 м и не следует за головой; панель материалов открывается справа и также остаётся на месте. Нажатие активируется при отпускании курка на той же кнопке; ползунки работают с удержанием. Удаление и выход требуют подтверждения внутри меню. Системные кнопки Meta/Menu не перехватываются. Захват работает только после попадания лучом в модель, двумя руками — по одной модели. Телепортация и ходьба исключают стены, пьедестал и габариты моделей. Скорости ходьбы и плавного поворота пропорциональны отклонению правого стика за пределами мёртвой зоны 18%; отпускание останавливает движение без инерции. Поворот идёт вокруг текущего положения головы.

На компьютере: левая кнопка — орбита камеры, правая — сдвиг, колесо — приближение. Параметры объекта находятся в правой панели. На узком экране панели открываются кнопками поверх сцены.

## AR для рисования на Quest 3

Нажмите **Войти в AR** в Meta Quest Browser. Приложение проверяет поддержку `immersive-ar` отдельно от VR. В AR виртуальная галерея скрывается, прозрачный рендер открывает passthrough; PBR-окружение и освещение моделей сохраняются. Камеры обрабатывает шлем, приложение не получает их изображения.

Во вкладке **Рисование** выберите модель через Art / Arch, нажмите **Поставить перед собой**, переместите её захватом. Масштаб: два захвата или правый захват + стик ↑↓. **Опустить на пол** использует `local-floor` шлема. Перемещайтесь физически: искусственная ходьба, поворот и телепортация в AR отключены, чтобы модели оставались на месте относительно реальной комнаты.

**Зафиксировать для рисования** блокирует трансформации, останавливает все анимации и автовращение, скрывает панели, контроллеры, лучи и выделение. **A / X** возвращает меню → **Снять фиксацию**; анимация продолжится с остановленной позы. **B** позволяет настроить материалы и выгрузить выбранную модель даже при фиксации. Новую модель можно добавить после снятия фиксации.

Размещение сохраняется только в текущем AR-сеансе: при выходе модели возвращаются на свои места в виртуальной галерее. Реальные поверхности не сканируются: перекрытие мебелью, глубина passthrough и постоянные пространственные якоря пока не реализованы. Стабильность привязки, высоту пола и удобство рисования нужно проверить на физическом Quest 3.

Справка: [Meta WebXR Mixed Reality](https://developers.meta.com/vr/documentation/web/webxr-mixed-reality/).

## Форматы и ограничения

**GLB/glTF рекомендуется для PBR и персонажей.** Материалы FBX/OBJ/DAE преобразуются в стандартные материалы, но не могут точно воспроизвести произвольные шейдеры DCC-программы. STL/PLY — геометрия, с цветами вершин при наличии. BLEND, MAX, C4D, CAD/STEP и USDZ нужно предварительно экспортировать в GLB.

Поддерживаются запечённые анимационные клипы. Ретаргетинг, IK-риг редактора, симуляция ткани/физики, пользовательские шейдеры и внешние отдельные анимации не импортируются автоматически. Hand tracking и многопользовательский режим в этот прототип не входят; управление рассчитано на Touch-контроллеры.

100% означает вписывание исходной модели в габарит 1,8 м. Это не гарантированный исходный масштаб в метрах. Размер ограничен диапазоном 5–1000% от вписанного размера.

Встроенные референсы публикуются вместе с сайтом и загружаются по выбору с показом прогресса. Новые позы занимают свободные места; уже загруженные модели, их положение и настройки материалов сохраняются. Повторный выбор загруженной позы переключает выделение без создания дубликата. В комнате до 12 моделей, включая примеры и импортированные файлы. Кнопка «Выгрузить из комнаты» в меню материалов (B) освобождает геометрию, материалы, текстуры и анимации только выбранной модели. Каталог и сохранённые локальные файлы не удаляются; локальные файлы снова восстанавливаются после перезагрузки страницы. Качество не снижается. Исходные сканы статичны, без скелета; материалы адаптированы к PBR, специальные Unity-шейдеры не воспроизводятся точно.

Импортированные пользователем файлы остаются в браузере конкретного устройства, **на сервер не загружаются и между устройствами не синхронизируются**. Чтобы открыть файл на Quest, перенесите его на шлем или используйте ссылку. Удаление модели из коллекции удаляет локальную сохранённую копию. Импорт по URL требует CORS и повторного открытия ссылки после перезагрузки.

Лимиты: 100 МБ на импортируемый файл, 250 МБ на пакет, 12 моделей. Для проверенных встроенных GLB с полным набором карт предел загрузки — 250 МБ. Они защищают от очевидного перерасхода памяти, но не гарантируют производительность тяжёлых сцен. Для шлема предпочтительны оптимизированные сетки и текстуры. Настройка 72 Гц запрашивается, если её поддерживает устройство; фактическую частоту необходимо измерять на шлеме.

У Nat ослаблены основная normal-карта кожи (40% от исходной силы), мелкий рельеф пор и его затенение. Карты остаются полноразмерными; блеск и шероховатость материала не изменены.

## Разработка

Node.js 24 и pnpm 11.25.0:

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm preview
```

`predev` и `prebuild` копируют Draco/Basis декодеры, создают демонстрационный GLB и локально размещают официальные профили/модели Touch Plus из `@webxr-input-profiles/assets@1.0.20`. Отсутствующие в исходном GLB узлы анимации системной кнопки исключаются из визуальных ответов, сохраняя исходную карту ввода. Сгенерированные файлы исключены из Git. Vite использует относительный base, поэтому сборка работает в подпапке GitHub Pages.

Для проверки без шлема откройте dev-сервер с `?xr`: включится официальный эмулятор Meta IWER 2.6.0 с профилем Quest 3, если нативный immersive VR недоступен. Тестовые объекты `window.__forma` и `window.__questDevice` доступны только в dev-режиме. Эмулятор и отладочный доступ исключены из production-сборки. Меню рисуется одной CanvasTexture по изменению состояния; для проверки изменений сериализуются только метаданные клипов, без ключевых кадров скелета.

## Публикация

В Settings → Pages выберите Source: **GitHub Actions**. Workflow `.github/workflows/pages.yml` проверяет тесты, собирает приложение и публикует `dist` при обновлении `main`. Скрипт `scripts/prepare-references.mjs` получает GLB из указанных для каждой модели релизов, сверяет длину и SHA-256 из `src/reference-catalog.js` и помещает их в `public/models/references`. Сборка завершается ошибкой при недоступном или повреждённом файле. В готовом сайте модели обслуживаются с того же домена GitHub Pages, без зависимости от CORS релизов. Проверенные локальные копии повторно не скачиваются. Ресурсы распределены между основным сайтом и репозиториями `formai-library-*`; каждый сайт содержит не более 850 МиБ моделей. `scripts/build-reference-catalog.py` сохраняет все 43 позы в каталоге и обновляет конкретный файл после публикации готового PBR GLB; версия в URL меняется вместе с SHA-256.

## Проверка прототипа

AR проверен на одном демонстрационном роботе в Meta IWER: прозрачный фон, выбор и перенос контроллером, аналоговый масштаб, запрет искусственной ходьбы/поворота, заморозка анимации и трансформаций, скрытие лучей/контроллеров, A/B, снятие фиксации, восстановление галереи и переход AR → VR → AR. 54 автоматических теста проходят. Эмулятор не проверяет реальный passthrough и стабильность трекинга в комнате.

Проверены в настольном Chromium: семь загрузчиков, GLB и FBX со скелетами и клипами, карты base/normal/roughness/metallic/AO/emissive на glTF-образце, пауза и смена клипов, сохранение файлов и восстановление коллекции, трансформации и адаптивный интерфейс. Автоматические тесты проверяют ограничения импорта, URL, пути ресурсов, диапазон масштаба и изменение костей скелета.

**Проверка на физическом Quest 3 ещё не выполнена.** Перед использованием на шлеме проверьте вход/выход WebXR, высоту пола, обе руки, захват, жест масштабирования, телепортацию, поворот и стабильность кадров на ваших моделях.

VR-интерфейс проверен в Chromium с Meta IWER и профилем Quest 3 через события эмулированных контроллеров: кнопки/ползунки лучом, отмена нажатия при отпускании на другой кнопке, сцена, клипы и перемотка скелетной анимации, захват одной/двумя руками, отпускание при отключении контроллера, телепортация, поворот, плавное движение правым стиком, остановка при потере фокуса или отключении контроллера, вызов меню и выход с восстановлением веб-панелей. Это функциональная проверка; эмулятор не подтверждает читаемость оптики, тактильный отклик и частоту кадров на настоящем шлеме. Дополнительные unit-тесты проверяют геометрию целей, отсутствие пересечений, пагинацию, двухручную математику и запрет телепортации в препятствия.

## Карты исходных материалов

У Ariel и Chloe перенесены цветовые микродетали кожи; у Nat — нормали, AO (R), cavity (G), curvature (B), сухая и влажная карты specular RGB / roughness A, микронормали с маской, lookup рассеяния, цвет обратного рассеяния и sheen-маска. У глаз всех трёх моделей — нормали и отражения. Нормали Unity DXT5nm преобразованы в XYZ с учётом переворота UV V. Все карты имеют полную цепочку mip-уровней и исходное разрешение. Корнеальные отражения используют прозрачное смешивание без чёрной поверхности и непрозрачной тени.

Оригинальные закрытые Unity-шейдеры адаптированы к Three.js PBR; побитовое совпадение рендера не предполагается. Runtime RenderTexture для интерактивного рисования влажности не является сохранённой картой: вместо него используется слабое равномерное смешивание поставленных dry/wet-карт. Обработка применяется только к версионированным материалам FORMAI; сторонние GLTF не изменяются.

### Spatial models / Gaussian Splatting

Art contains the original `vrgirlz ariel cream outfit 024 spatial model` folder with Ariel · Cream Outfit 024. The original 126,151,691-byte PLY is fetched from the existing release at build time, verified by SHA-256, and served from Pages under `models/spatial/`. All 508,670 Gaussians and SH3 are loaded with Spark 2.4.0, float32 positions and no LoD reduction. The original file is unchanged.

Gaussian PLY is detected by its vertex properties; ordinary triangle PLY still uses Three's PLYLoader. Binary little-endian float32 3DGS PLY is supported, up to 250 MiB and 2 million splats per file. Generic imports assume the conventional COLMAP Y-down coordinates. This model has baked appearance, no PBR maps or skeletal animation. The B panel provides live splat appearance controls and unloading.

The renderer is lazy-loaded, shares the WebXR scene and alpha passthrough, and uses radial sorting. Bounds support framing, AR placement and scale. Controller selection uses an invisible bounds proxy to avoid scanning all Gaussians per pointer per frame. Removing the last spatial model disposes its renderer and sort workers.

Quest Browser creates a context without MSAA (also exercised by the dev IWER profile). While splats are present in either immersive mode, dynamic shadow passes are disabled, foveation defaults to 0.35, and Gaussian tails use Spark's recommended VR `maxStdDev = sqrt(5)`. Source splats, SH3 and framebuffer resolution are unchanged. PBR lighting and materials remain available, but mesh shadows are absent while this immersive splat profile is active; prior shadow/foveation/footprint settings return on exit or unloading the last splat. This addresses the reported [Quest MSAA + shadows + Spark rendering issue](https://github.com/sparkjsdev/spark/issues/400) and reduces transparent overdraw per [Spark's performance guidance](https://sparkjs.dev/docs/performance/). A full page reload is required to recreate an old MSAA context. The user reported corruption and stuttering on Quest 3 with Ariel alone in both VR and AR; the user subsequently confirmed smoother rendering, but the stepped colors around the figure’s silhouette remain. Emulator tests do not establish headset frame rate or passthrough quality.

The extended accumulator also preserves float32 centers and fp16 colors after camera transforms instead of re-packing them to the compact representation. In immersive mode only, splat materials use straight-alpha blending to avoid pre-multiplication of very small color contributions ([Spark's posterization investigation](https://github.com/sparkjsdev/spark/issues/36#issuecomment-3444040846)); canvas/XR alpha conventions remain unchanged. Ariel has 49% of splats below 5% opacity and 80% below 10%, making low-opacity blending a relevant path to investigate. The user reports stepped colors at viewing distance which improve very close up. The user’s physical Quest re-test confirmed that performance improved while the color defect remained; the upstream posterization report was reproduced on Nvidia, not a confirmation of the same defect on Adreno.

Renderer documentation: https://sparkjs.dev/docs/spark-renderer/ and https://sparkjs.dev/docs/splat-mesh/ (Spark MIT).

### Настройки сплат-модели в VR / AR

При входе в VR/AR с выбранной сплат-моделью или её загрузке внутри сеанса панель открывается рядом с фигурой. **B** открывает/закрывает её, **A** открывает основное меню, **Y** или кнопка фокусировки переносит панель перед пользователем. Панель следует за перемещением/масштабированием модели, но не за движением головы. Ползунки управляются лучом и удержанием триггера; рядом отображаются числовые значения.

Четыре вкладки содержат 15 настроек. «Модель» — непрозрачность, яркость и степень SH только выбранной фигуры. «Контур», «Смешивание» и «Детализация» меняют общий рендерер всех сплатов: ширину контура, порог прозрачности, сглаживание, дополнительное размытие, затухание, резкость проекции, способ смешивания, сортировку, фовеацию, ограничения размера сплата и запас за кадром. Пределы параметров соответствуют их единицам; максимальное значение не обязательно означает лучшее изображение.

Настройки хранятся локально в `formai.splat-settings.v1`. Рендерер имеет отдельные профили экрана и VR/AR; свойства выбранной модели общие для обоих режимов. «Сбросить настройки» восстанавливает выбранную модель и текущий профиль рендерера. Исходный PLY, количество сплатов, разрешение XR-кадра и отключение MSAA не меняются. Настройки не синхронизируются между устройствами.

После выхода из VR/AR в веб-режиме **того же браузера** кнопка «Скопировать значения экрана и VR» даёт JSON с обоими профилями и свойствами модели. «Показать значения для копирования» позволяет скопировать текст вручную. Этот набор можно передать для настройки будущих значений по умолчанию. Подбор параметров и оценка дефекта контура требуют физического Quest; эмуляция проверяет управление и сохранение.
